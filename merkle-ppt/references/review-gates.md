# Merkle PPT review gates

Review the deck as a complete story, then every slide at full size. A good source template and valid file do not by themselves prove visual quality.

## Before visual polish

- Each page has a clear task and accurate title. Factual claims and numbers match the supplied sources; audience can distinguish current facts, assumptions, targets, and recommendations.
- Charts include the object, unit, comparison, time period, scale, and source needed to interpret them. Arrows, overlap, color, and proximity show only real relationships.
- The deck follows the requested page count, order, wording, and scope. A narrow edit preserves unrelated content and objects.

## Full-deck and per-slide inspection

- In thumbnail view: coherent Merkle identity with useful variation in dark/light balance, density, images, and page geometry. No long run of identical cards unless the comparison requires it.
- At full size: first focal point, reading path, contrast, safe margins, alignment, line breaks, labels, photo crop, and logo clear space are sound.
- Check the actual bounds and visible text of every populated text box, including inherited placeholders that have been resized. Ensure each has positive width and height, fits within its intended area, and does not clip or overflow.
- Closing slides keep the template M mark and copyright line. Add slide-level text only when the user explicitly requests it.
- If the optional gradient divider is used, check that a single horizontal or vertical strip separates exactly two content blocks. [Gradient divider settings](brand-profile.md#optional-gradient-divider-for-two-content-blocks)
- Check shadow settings for flat pictures and optional 3D picture stacks. When pictures overlap, check separation between layers and ensure essential information is readable. [Picture effects](brand-profile.md#layout-and-imagery)
- Fonts: English Arial Regular and Chinese 微软雅黑 Regular by default. Check mixed runs, fallback substitution, and the result in the target PowerPoint environment. Do not infer exact type quality from a converter render alone.
- Brand: use appropriate unmodified supplied logo; apply current official rules where available; check image/prism and icon use. Remove all template instructions, placeholders, old customer names, historical numbers, and example claims.
- Template structure: verify that each new slide links to its intended named official layout and uses native placeholders according to their prompts. For a user-specified custom composition, verify the link to `自定义版式` and check that the slide objects remain editable. Confirm that general light-background content slides inherit the M avatar and slide number. Verify dentsu is present only where explicitly requested. [Footer geometry](content-page-footer.md)
- Editability: ordinary text, lines, process shapes, tables, and basic data charts remain native and practical to edit. Raster assets are acceptable for photos, approved brand artwork, and complex texture.
- Delivery: all slides render; no clipping, overlaps, missing assets, broken links, or unreadable source notes. Inspect dynamic or animated content in PowerPoint when present.

If a defect appears only in LibreOffice or another converter, compare it with the source PPTX and PowerPoint before attributing it to the design. Report any remaining material limitation precisely.
