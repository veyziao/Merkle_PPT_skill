# Source object styles: Slide, Case, Diagram and QBR libraries

When adapting or faithfully reconstructing a specific source example, use the original PPTX as the authority and locate the source slide and shape, then inspect its direct formatting and inherited theme/layout/master before rebuilding. The following compressed JSON files provide a detailed object-level locator and source XML snapshot:

- [Slide Library object styles](slide-object-styles.json.gz), source [Slide Library for ai.pptx](../assets/Slide%20Library%20for%20ai.pptx).
- [Case Library object styles](case-object-styles.json.gz), source [case library - Case Study Layout Types.pptx](../assets/case%20library%20-%20Case%20Study%20Layout%20Types.pptx).
- [Diagram Library object styles](diagram-object-styles.json.gz), source [Diagram library - Diagram Elements.pptx](../assets/Diagram%20library%20-%20Diagram%20Elements.pptx). The separate [diagram shape style index](diagram-shape-styles.json) additionally parses selected geometric shapes into a convenient explicit-effects view.
- [QBR Library object styles](qbr-object-styles.json.gz), source [QBR SLIDE LIBRARY.pptx](../assets/QBR%20SLIDE%20LIBRARY.pptx).

Each `.json.gz` contains the source SHA-256, source slide/part, layout/master part, slide background XML, object IDs, group hierarchy and coordinates, fill summary, complete object XML and shape-properties XML. It also includes source theme and layout/master definitions and slide relationships. Object XML preserves the native definitions for fills and gradient stops, alpha/color transforms, line, shadows and effect lists, scene 3D and shape 3D, geometry, text formatting, picture crop and image effects where present. The original PPTX remains necessary for linked or embedded media, relationships, charts and final rendering.

Read by slide and shape ID rather than loading all decks into a prompt. In Python, for example, `json.load(gzip.open(path, 'rt', encoding='utf-8'))`, then select `slides[slide_number - 1]['shapes']` and match `shape_id`. Coordinates inside groups are group-relative; use the original nested group transforms when reconstructing. Preserve z-order, connectors, grouping and text wrapping along with the style; inspect image effects and layers. Theme colors, color transforms, opacity transforms and omitted properties must be resolved against the source theme/layout/master; omitted properties do not prove a blank fill or absent effect. Different source object variants should retain their own styles rather than being normalized into one common preset.

Recreate required shapes, text, lines and diagrams with editable native PowerPoint objects; use the original authorized picture or vector assets where appropriate. Use the user's approved Arial / 微软雅黑 fonts and template unless the user explicitly requests exact source typography instead. Source examples can differ from approved defaults: preserve the distinction and explicitly ask only if a conflict materially changes the requested output. Validate the final slide in the intended PowerPoint environment by comparing the source and output at slide and detail level, including text fit, theme/gradient appearance, 3D and effects. A property capture is not proof of pixel-identical output across PowerPoint versions, fonts, or renderers.

Style precedence: current explicit user directions first; then the particular source object's effect when the requested task is to reproduce it; then the brand profile's default for ordinary new elements. Source business facts and labels are not inherited. Check the actual selected object's properties, because visually similar library variants may have different fills, transparency, shadow, 3D or theme dependencies.
